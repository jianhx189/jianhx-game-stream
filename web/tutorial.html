GUIDE / MINISTREAM 2.2

从安装，
到第一次连接。

适用于 MiniStream 2.2。先确认两端角色，再验证隧道认证、UDP 通路与实际媒体。请只连接自己拥有或获授权的设备。

01 / 先确认两台电脑的角色

被控端（Host）是实际运行游戏和桌面的主机；主控端（Client）是你用来查看画面、操作鼠标键盘的电脑。两端使用分端工作台，不要在被控端与主控端之间混淆安装包。

准备两台 Windows 电脑、实际可达的网络路径、隧道凭据和 Sunshine 管理信息。Windows 需要与程序架构匹配的微软 Visual C++ v14 运行库；请从微软官方页面获取，不要下载散装 DLL 替换系统文件。

微软运行库说明 ↗

服务管理和安装可能需要 Windows 管理员授权。当前尚未完成“没有 ISO 或管理员权限”的限制环境验收，不能据此宣称此类环境可用。

02 / 在主机安装被控端

下载并安装 Host，保存自己的隧道口令和 Sunshine 管理信息。被控端工作台可查看端口监听、真实认证会话、遥测历史和事件，也可管理服务、修改端口和导出诊断。

“本机已监听”只说明本机端口存在监听，不等于 FRP、公网或 UDP 通路已验证。首次使用还需在主控端测试连接与配对；需要 PIN 时，从被控端打开 Sunshine 管理页面完成授权。

新安装的隧道口令为 12–64 个字母、数字或 _ . @ -；升级保留的旧口令可以继续使用，但建议轮换。隧道口令经标准输入交给后台，不进入命令行、计划任务或安装日志。配置与日志 ACL 用于限制本机文件访问，不是端到端加密。

重启和停止服务会中断远程使用，操作前确认没有正在使用的会话。管理命令可能请求管理员授权，取消授权不会应用对应配置变更。

03 / 在另一台电脑打开主控端

下载并安装 Client。选择局域网或 FRP，填写自己的地址、端口和隧道口令。Sunshine 管理密码用于自动配对，可留空并采用手动 PIN 流程；不要把文档示例地址当成公共服务器。

测试连接后检查主机卡片是否在线和已配对，再进入应用列表。隧道认证成功不代表游戏串流已经正常。进入桌面后分别检查画面、声音、鼠标和键盘。

串流时用 F12 或 Ctrl+Alt+Shift+X 打开菜单，切换鼠标模式、统计、显示方式或断开连接。游戏通常更适合相对坐标；普通桌面按实际体验选择。

2.2 的主控端工作台用于设备、配对与媒体遥测，被控端工作台用于服务、链路与认证会话。两端均新增真实遥测历史和事件；没有数据或样本过期时显示“—”，不要用历史空值推断网络正常。

04 / 局域网与跨网络连接

同一网络先使用主机局域网 IPv4 验证。跨网络再配置自己的 FRP 或其他可信网络。mslink 默认对外提供 TCP 14738 与 UDP 14739，实际端口以安装配置为准。

  1. 先确认被控端服务正在监听，主控端可以通过局域网完成认证与配对。
  2. 在自有网络入口分别配置 TCP 与 UDP 映射，并同步检查本机与网关防火墙。
  3. 将主控端地址与端口改为实际外部映射值，再次测试连接和双向 UDP。
  4. 最后启动实际媒体，结合双端历史与事件判断问题发生在认证、隧道还是媒体阶段。

FRP 的 UDP 代理可能由其他传输协议承载，请核对服务端、客户端和服务商的实际设置。不要公开转发 Sunshine 管理页面作为日常串流入口。修改被控端端口后，还需同步修改主控端、映射与防火墙；控制台不会自动开放公网访问。

05 / 读懂遥测，不把指标混为一谈

2.2 的历史与事件来自真实程序上报，用于比较一段时间内的状态，不是根据截图或设备型号估算的性能分数。

指标表示什么不表示什么
隧道 RTT隧道链路的往返时间端到端操作延迟或游戏内延迟
抖动链路到达时间的变化程度画面帧率或解码耗时
吞吐量观察窗口内实际传输的数据量趋势运营商标称带宽或画质承诺
网络丢帧主控端媒体接收中的网络相关丢帧IP 丢包率
解码 / 排队时间主控端处理媒体的对应阶段耗时被控端编码耗时或完整输入延迟
帧率主控端实际上报的媒体帧率被控游戏引擎的瞬时或最高帧率

先记录事件发生时间，再对照同时间段的遥测趋势。单次高值不能独立证明根因；“—”表示缺失或过期样本，不是 0，也不是正常。

06 / 弱网与常见问题排查

画面卡顿、断续或掉回 TCP

  • 先用同一局域网复现。如果局域网稳定而跨网异常，优先检查映射、双向 UDP、返回源端点和中间链路。
  • 同时查看被控端隧道 RTT、抖动与事件，以及主控端网络丢帧、解码和排队时间；不要只看单个指标。
  • 降低码率或分辨率可作为对照实验，但不是对所有链路的固定优化值。每次只改一项并记录结果。
  • 持续 TCP 回退时，检查有效 ACK 与 UDP 回包的源地址、源端口，而不只是确认“发出过 UDP”。多网卡主机尤其要核对回包路径。

按状态处理

  • 窗口消失：查看任务管理器，区分退出与托盘隐藏。真实崩溃时收集事件查看器的故障模块、代码和时间。
  • 服务未监听：检查被控端安装目录与日志，通过工作台启动相应服务，不要同时启动多个实例。
  • 画面正常但鼠标失效：让串流窗口获得焦点、关闭菜单，检查鼠标模式并保留双端日志。
  • 公网连接失败：先测局域网，再检查映射、防火墙、双向 UDP 和凭据；本机绿灯不能证明公网可达。
  • 提示无法解密口令：dpapi:v1: 密文只能由保存它的 Windows 用户解开。换用户、换机器或回退旧版后重新填写，不要手工修改密文。

主控端运行日志通常在 %TEMP%/Moonlight-*.log，隧道日志回退位置为 %TEMP%/MiniStream/mslink.log。可提供与复现时间对应的新日志和脱敏诊断报告；分享前检查设备、进程和地址信息，不要公开凭据或崩溃转储。

07 / 升级、验证范围与安全边界

先结束当前串流并保存配置，再配套升级两端。覆盖升级时保留已有安装目录，避免旧版 x86 路径与新版默认路径并存。2.1.4 已修复主控首次保存失败与 mslink 启动失败残留 socket，2.2 延续这些修复；回退到 2.1.2 或更早版本、或更换 Windows 用户后需要重填口令。

主控端 DPAPI 与被控端文件 ACL 只保护本机文件，同一 Windows 用户仍可解密，程序内存中仍有明文，网络传输也不因此受到保护。自定义隧道认证不是经过审计的端到端加密 VPN；公网部署请使用可信受保护的网络路径。

已验证：本机 CTest 7/7；7 类弱网场景的 50/50 项检查通过。
未验证：完整干净 Windows 虚拟机安装，以及没有 ISO 或管理员权限的限制环境。未宣称 Windows 10/11 全部环境、所有 GPU/驱动组合或所有游戏均已测试。

工程测试和受控弱网检查不等于高码率、长时间真实跨网游戏全面验收。实际帧率、延迟与输入体验取决于设备、驱动和链路。发布文件与 SHA-256 以 2.2 更新页 和对应 GitHub Release 为准。
