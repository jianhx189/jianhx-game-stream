RELEASE / 热修复

MiniStream 2.1.4

修复 2.1.3 的主控首次保存失败与启动失败残留 socket，并修正空口令与上游连接失败的处理。

下载被控端 ↓下载主控端 ↓

这次修了什么

  • 主控端首次连接时 mslink.ini 还不存在，2.1.3 保存必定失败、之后每次都要重填；2.1.4 在文件不存在时也通过 QSaveFile 原子创建配置。
  • 2.1.3 的 mslink 启动失败会泄漏监听 socket，带 47990 的隧道回退重试可能二次 bind 并卡住首次连接；2.1.4 在失败路径关闭全部 socket、调用 WSACleanup，并校验 listen/bind 地址为 IPv4。
  • 空口令会被拒绝，且不会删除已保存的 dpapi:v1: 密文。
  • 上游 Sunshine 目标连接失败时发送 StreamClose，客户端立即结束对应流，不再等到超时。

安装建议：2.1.3 存在上述回归，不建议用于全新安装，新装请用 2.1.4。已安装 2.1.3 的用户覆盖升级即可，配置、隧道口令、Sunshine 配对与 DPAPI 凭据都会保留。

安全边界

2.1.4 沿用 2.1.3 的 DPAPI 与 ACL：只保护同一 Windows 用户可解的本地文件，程序内存中口令仍是明文，网络传输也没有因此加密。自定义隧道认证与 TCP 明文会话密钥没有变化，不是端到端加密 VPN。回退到 2.1.2 及更早版本、或更换 Windows 用户后需要重新填写口令；此前分享过隧道/Sunshine 口令的，请立即轮换。

升级与校验

结束当前串流，在已有安装目录覆盖升级并保留个人配置，两端建议使用相同版本。升级不会要求重新配对；回退旧版仍需重填口令。只打开新面板不会升级旧后台。

用 PowerShell 的 Get-FileHash 文件名 -Algorithm SHA256 与同版 SHA256SUMS.txt 对照。Release 同时提供构建清单和源码；哈希在 2.1.4 安装包编译完成后生成，不能沿用 2.1.3。

验证范围

2.1.3 已完成本机回环 CTest 4/4 与 --password-stdin 启动实测。2.1.4 增加启动失败重试与上游失败关闭测试并重建全部组件，最终 CTest、两端构建与安装包结果以发布清单记录为准，本页不预先宣称已通过。干净 Win10/Win11 安装、所有 GPU/驱动组合、高码率弱网与长时间跨网串流尚未验收；2.1.2 的真实转发 UDP 修复结论沿用，新的真实链路媒体串流仍需单独验收。
