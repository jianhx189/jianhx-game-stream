V2.2.0 / CURRENT

MiniStream 2.2

  • 真实遥测历史：保留实际程序上报的趋势，帮助对照一段时间内的链路与会话状态；缺失或过期样本仍显示“—”。
  • 事件记录：把连接、服务与遥测变化放到可回看的事件中，辅助定位问题发生的时间。
  • 分端工作台：主控端聚焦设备、配对和媒体，被控端聚焦服务、链路和认证会话。
  • 延续 2.1.4 修复：包含主控首次保存失败、mslink 启动失败残留监听 socket 等问题的修复。

2.2 改善的是状态可见性与工作流，不宣称因此降低延迟、提高帧率或解决所有弱网问题。

下载、升级与校验

结束当前串流并保存配置，在已有安装目录覆盖升级，两端建议使用相同版本。发布清单尚未生成时，下载按钮只进入 v2.2.0 标签页；脚本不会把旧版 release.json 资产当作 2.2 安装包。

发布文件生成后，用 PowerShell 的 Get-FileHash 文件名 -Algorithm SHA256 与同版 SHA256SUMS.txt 对照。校验值必须来自实际构建，不能沿用旧版。

指标与安全边界

隧道 RTT 不是端到端操作延迟，媒体网络丢帧不是 IP 丢包率。排障时结合双端事件、RTT、抖动、网络丢帧、解码和排队时间，不用单项数据代替完整链路。

DPAPI 与文件 ACL 只降低本机文件泄露面；同一 Windows 用户仍可解密，内存中的口令仍是明文，网络传输也没有因此加密。自定义隧道认证不是经过审计的端到端加密 VPN。公网请使用可信受保护的网络路径，不要公开 Sunshine 管理页面。

V2.1.4 / PREVIOUS HOTFIX

2.1.4：首次保存与启动清理

修复 2.1.3 主控端首次连接时 mslink.ini 不存在导致保存失败的问题，以 QSaveFile 原子创建配置；修复 mslink 启动失败泄漏监听 socket 与回退重试二次 bind 的问题，并改善空口令和上游 Sunshine 连接失败处理。2.2 延续这些修复。

从 2.1.3 升级前结束串流并保存配置。回退到 2.1.2 或更早版本、或更换 Windows 用户后，可能需要重新填写 DPAPI 凭据。

V2.1.3 / EARLIER

2.1.3：加固与已知回归

引入隧道队列、帧和握手加固，以及主控端 DPAPI 凭据、被控端标准输入口令与文件 ACL。该版本存在首次保存失败和启动清理回归，相关问题已在 2.1.4 修复。
