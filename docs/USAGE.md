# 使用说明

## 一、被控端（游戏主机上跑）

### 界面模式
双击 `ministream-host.exe`。首次运行会在 exe 旁生成 `host.ini`。
托盘图标右键菜单：**启动服务 / 停止服务 / 打开配置 / 退出**。

配置窗口里能改：端口、验证码、码率、帧率（30/60/120/144）、显示器（下拉列出所有屏幕）、
输入注入开关。改完点**保存**——重启服务后生效（托盘会弹气泡提醒）。

### 无界面模式（挂后台/开机自启推荐）
```
ministream-host.exe --headless
```
日志打到控制台并写 `host.log`。`Ctrl+C` 退出。

常用参数（都会覆盖 ini）：
```
--port 20000 --password xxx --fps 60 --bitrate 20000 --monitor 0
--encoder nvenc|amf|qsv|cpu     默认 auto，按 nvenc→amf→qsv→cpu 顺序挑第一个可用的
--log-level 0..4                0=Trace 4=Error
```

### host.ini 字段
```ini
[server]
port=20000          ; 必须 >10000，TCP 和 UDP 同端口
password=changeme   ; 留空会被拒绝启动
bind=0.0.0.0

[video]
fps=60              ; 30/60/120/144
bitrate_kbps=0      ; 0 = 按分辨率自适应（1080p60≈20Mbps）
width=0             ; 0 = 原生分辨率；要缩放就同时填 width 和 height
height=0
encoder=auto
monitor=0
keyframe_interval_sec=2   ; 丢包恢复速度 vs 码率开销的折中

[input]
enabled=true
```

## 二、FRP 配置

同一个端口要映射**两条**规则（TCP 和 UDP 各一条），例如：

```ini
[[proxies]]
name = "ministream-tcp"
type = "tcp"
localPort = 20000
remotePort = 20000

[[proxies]]
name = "ministream-udp"
type = "udp"
localPort = 20000
remotePort = 20000
```

## 三、远控端（本地电脑上跑）

双击 `ministream-client.exe`，打开连接面板：

- **连接区**：一个输入框直接粘 `IP`、`IP:端口`、`域名` 或 `域名:端口`（不写端口默认 20000）；
  验证码 + "记住验证码"；红字错误**就地显示**，绝不弹窗
- **画质区**：预设（均衡 / 画质优先 / 流畅优先）一键切换，自动联动
  分辨率（原生/1080p/1440p/4K/1600x900/720p）、帧率（30/60/120/144/240）、
  码率（自适应/8/15/20/30/50/80 Mbps）；手动改任一项自动落到"自定义"
- **选项区**：连接后全屏、显示悬浮状态条
- 连接失败会**带着错误信息回到面板**（不用重填参数），改完直接再点连接

### 远程中的小悬浮按钮 + 顶部工具栏

连上后屏幕顶边中间会有一个**半透明小胶囊（≡）**：

- **点一下** → 展开顶部工具栏（3 秒无操作自动收起，小胶囊自动回来）；
- 鼠标移到屏幕顶边 / 按释放键鼠快捷键（`Ctrl+Alt+Shift+Q`）也能唤出；
- 小胶囊不抢焦点（点击不会打断游戏捕获），悬停会变亮。

工具栏内容：
- 状态行：分辨率 · 帧率 · 码率 · 延迟 · 丢帧率 · 队列 · RTT（走 TCP 兜底时会显示 `TCP兜底`）
- **画质 ▾**：展开面板改预设 / 分辨率 / 帧率 / 码率 / 关键帧间隔，点「应用」立即生效
  （每行都有文字标签，面板是深色自绘风格；10 秒无操作自动收起）
  - 只改码率、关键帧间隔 → **热调**，不断流
  - 改分辨率/帧率 → 自动走重协商，画面中断约 0.5 秒后恢复
- 全屏/窗口切换（全屏时可切**缩放模式**：智能缩放/拉伸/1:1）、悬浮条开关、断开连接
- 工具栏**不抢焦点**（WS_EX_NOACTIVATE），点完按钮焦点自动回渲染窗口

> 链路不稳定自动切 TCP、恢复后自动切回 UDP 时，只在顶部弹出**半透明小胶囊提示**
> （约 3 秒），不会再用大字糊住整个画面。

### 键鼠捕获（重点）
- 连上后自动接管键鼠；**Ctrl+Alt+Shift+Q** 释放 / 重新捕获
  （在 client.ini 的 release_hotkey 改）
- 未捕获状态下按 **ESC** 退出会话
- 捕获期间低层键盘钩子会吞掉 Win、Alt+Tab 等系统键，避免游戏里被切出去
- 被控端断线时会自动抬起所有按键——不会出现"W 一直按着"的卡键

### 鼠标模式（重点：解决"光标乱飘/不像自己的鼠标"）

鼠标模式是**自动**的，按被控端"系统光标当前是否可见"切换：

| 场景 | 模式 | 你看到的效果 |
|------|------|--------------|
| 桌面 / 游戏菜单（有系统光标） | **绝对映射** | 远端光标 = 你本机鼠标位置，**1:1 重合**，不吃 Windows 鼠标加速，不会飘 |
| 游戏内场（游戏把光标藏起来） | **相对模式** | 本机光标隐藏，发原始位移，游戏读 Raw Input（FPS 瞄准手感） |

- 绝对模式下**不额外画一个远端光标**：你屏幕上的那个光标就是被控端的光标，
  所以不会出现两个鼠标/拖影；菜单和桌面里的点击位置也和看到的完全一致。
- 切换点会写进 client.log：鼠标模式 -> 绝对映射 / 鼠标模式 -> 相对模式。
- 想强制某种模式：client.ini 的 [input] mouse_mode = auto|absolute|relative，
  或环境变量 MINISTREAM_MOUSE_MODE=auto|absolute|relative（排障用）。

### 远端光标形状
被控端还会把**光标图片本身**（箭头/手型/文本光标等，含热点）实时发过来，
所以形状变化也能看见。只有在相对模式 + 被控端光标可见这种组合下才会由远控端
自己画光标；正常情况下用的都是系统/游戏自己的光标。

### 声音（被控端 → 远控端）
- 被控端把**系统正在播放的声音**（游戏/音乐）用 WASAPI loopback 录下来，
  Opus 96kbps / 48kHz 立体声 / 20ms 一帧传过来，远控端直接播放；
- 正常走 UDP（每包发两份抗丢包），视频切 TCP 兜底时声音自动也走 TCP，不断音；
- 播放侧 40ms 抖动缓冲、超 90ms 自动裁剪，延迟不会越积越大；
- 被控端 host.ini：
  `ini
  [audio]
  enabled=true
  bitrate_kbps=96
  `
- 远控端 client.ini：[audio] enabled=true（工具栏「声音」可以随时本机静音）

### 锐化（游戏画面细节）
编码 + 缩放会把细节糊掉，游戏里的字和远处目标尤其明显。画质面板里的
**锐化**下拉（关/低/中/高，默认低）在客户端着色器里对**亮度**做反锐化，
色度不动（不会有红绿描边），改完立刻生效、不用重连。
会话里改过会记住到下次；也可以写死在 client.ini：

`ini
[video]
sharpen=1        ; 0=关 1=低 2=中 3=高
`

### 右上角悬浮条
FPS / 码率 / 丢帧率 / 队列深度 / 端到端延迟 / RTT / 解码耗时 / 硬解还是软解 / 编码器名。
连接面板里可关，工具栏里也可切换；`client.ini` 里 `overlay.corner` 选四角
（0 左上 1 右上 2 左下 3 右下）。

### 命令行（自动化/脚本用）
```
ministream-client.exe --auto --host 1.2.3.4 --port 20000 --password xxx ^
                      --fullscreen 1 --overlay 1 --seconds 60
```
`--auto` 跳过连接界面直接连；`--seconds N` 到点自动断开。

## 四、性能与延迟

| 现象 | 处理 |
|------|------|
| 延迟高、画面但很流畅 | 检查是不是开了垂直同步（默认已关）；确认没有中间层在转码 |
| 丢帧率不为 0 | 把 `keyframe_interval_sec` 调小（恢复更快），或降码率/帧率 |
| CPU 占用高 | 看被控端日志里 `编码器` 是不是落到"软件"；NVENC 不可用时检查驱动 |
| 画面颜色发灰/偏色 | 理论上不会：GPU 路径显式设了 BT.709 limited range，CPU 回退路径同参数 |

## 五、排障顺序

1. **先跑 `ministream-videoprobe 5 0 60 auto`**——它把采集和编码单独拎出来测。
   它都失败就别怀疑网络和界面。
2. 被/远控端的 `host.log`、`client.log`（UTF-8，带 BOM，记事本直接看）。
   日志级别调到 `--log-level 1` 能看到渲染路径、握手每一步。
3. **连不上**：FRP 的 TCP 规则；防火墙；端口必须 >10000。
4. **连上了但没画面**：FRP 的 **UDP** 规则没配（最常见）。UDP 不通时视频全丢，
   控制通道还在，表现为"已连接但黑屏、丢帧 100%"。
5. **自检**：`ministream-selftest.exe` 必须 125/125 全过。
   （其中包含"并发停止服务"和"会话进行中停止"的生命周期回归——
   这一类问题以前会让被控端直接闪退。）

### 关于鼠标和传输兜底（这两个问题的解决办法）

- **鼠标**：远控端画的是被控端**真实系统光标**（位置/图片/可见性都由被控端实时发过来），
  菜单里有、游戏内场自动隐藏，和本机玩一致。一直看不到鼠标时，先看 client.log 有没有
  收到远端光标形状；没有就看被控端 host.log 里的 [光标] 形状查询 几行（带 hr 和尺寸）。
- **传输兜底**：UDP 视频断流或大面积丢包时会自动切 **TCP 传视频**（画面不花不闪，延迟略高），
  之后每几秒探测一次 UDP，网络一好自动切回低延迟的 UDP。工具栏状态行出现 TCP兜底
  就表示当前在走 TCP；这不是故障，是链路自愈后的状态。
## 六、闪退了怎么办：crash.log 与 minidump

以前如果程序出问题，你只会看到它"黑一下然后没了"，Windows 顶多弹个"程序已停止
工作"，什么线索都没有。现在两端都装了崩溃自诊断，**任何**未捕获异常、访问越界、
CRT 参数错误都会在程序自己所在目录留下两样东西：

| 文件 | 内容 |
|------|------|
| `crash.log` | 时间、崩溃类型（例如 `std::system_error`）、`what()` 文本、调用栈（模块+偏移） |
| `crash_<host\|client>_<pid>.dmp` | 标准 minidump，可以用 `工具\minidump_info.py` 解析出精确调用栈 |

遇到闪退的正确姿势：

1. 打开 `crash.log`，最后一段就是原因。例如
   `类型: std::system_error  what(): ...` 说明是并发/线程收尾问题。
2. 想看精确调用栈（需要符号）：
   ```
   python 工具\minidump_info.py crash_host_12345.dmp
   ```
   有 `.map`/`.pdb` 时加 `--exe <exe路径> --map <map路径>` 能把地址翻译成函数名+行号。
3. 崩溃后进程会安静退出（被控端退出码 3=未捕获异常、4=访问越界、5=CRT 参数错误），
   不再弹系统错误框——这是一份能直接拿来排查的记录，而不是一句"闪退"。

## 七、两个容易踩的坑（已用代码堵住，说明一下行为）

- **同一台机器只能有一个被控端。** 起第二个会直接提示"已经有一个被控端在运行"
  并退出（退出码 6）。以前允许起两个时，两个进程会抢同一端口、同时写同一个
  `host.log`（日志互相覆盖成乱码），连接还会被其中一个吃掉，表现成
  "连上了却永远收不到 Challenge"。
- **在托盘里改完配置点"保存"会立刻生效**：服务会按新端口/新密码重新监听，
  不用重启程序。如果保存的内容和当前生效的一模一样，则什么都不做，
  **不会打断正在进行的会话**。

## 八、安全边界（自用工具，明确说清楚）

- 密码走挑战-应答（HMAC-SHA256），不在网络上传输，防重放，常量时间比较
- **视频流本身不加密**。同网段抓包能看到画面内容。要加密的话最省事的位置是
  UDP 载荷上套 ChaCha20，密钥从现有 `key` 派生，协议头不用动（见 PROTOCOL.md §2.3）
- 被控端默认监听 `0.0.0.0`。只想内网用就把 `bind` 改成本机内网 IP
