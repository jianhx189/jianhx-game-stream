# MiniStream 2.1.0 UI 预览版

本次交付包含实际可运行程序、安装包与源代码，不只是网页原型。保留原有正式版 2.0.5，新增独立预览版，便于先验收界面与管理功能。

## 已实现

- 主控端：原创森林绿 / 浅绿品牌图标（SVG、Windows 多尺寸 ICO），统一深色界面、设备卡片、在线与配对状态、明确的连接设置入口和空状态说明；连接向导居中显示。沿用原有配对、设备与应用入口。
- 主控端配置：连接配置改存 `QStandardPaths::AppLocalDataLocation/mslink.ini`，启动读取和界面保存使用同一路径。安装包不写入预设服务器，不再要求普通用户向 Program Files 写配置。旧版目录中的连接配置需要用户在新版向导重新填写。
- 被控端：新增 Qt Widgets 原生控制台。概览查看 Sunshine HTTP 与 mslink TCP 的本机监听；基础设置调整 TCP/UDP 端口与 Sunshine 超时；日志页读取日志尾部、隐藏凭据行与 IPv4 并导出诊断。
- 服务操作：启动、停止、重启经固定 PowerShell 管理脚本请求 UAC；停止进程限定在安装根目录内，停止/重启先提示中断。取消 UAC 不执行操作。保存配置保留未修改字段、建立备份，准备两份文件后再替换，异常尝试回滚。保存后主动重启，端口变更需另行同步客户端、映射与防火墙。
- 安装集成：被控端桌面及开始菜单入口指向控制台。两端配套部署 VC143 CRT，避免仅依赖用户系统中已有的旧版运行库。
- 官网：加入四张真实运行窗口截图，新增 `tutorial.html`，区分 UI 预览版与正式版，不将本机监听宣称为公网连通。

## 本地位置

- 预览安装包及 SHA-256：`安装包/UI-Preview/`。
- 主控端便携运行目录：`构建产物/client-preview/`，运行 `MiniStream.exe`，依赖整套目录，不能只复制 EXE。
- 被控端控制台：`构建产物/host-ui/`；运行 `MiniStreamHost.exe --root <已经安装的被控端根目录>`。完整安装包会自动接入该目录。

- 被控端控制台与管理脚本：`源码/host-console/`；打包脚本：`源码/安装包脚本/`。
- 网站：`web/`，发布目录：`web/dist/`；素材：`web/assets/`。

## 构建衔接

主控端是 Moonlight-Qt 的源码覆盖层，不是根目录旧版自研客户端的 CMake 目标。基线 Moonlight-Qt 提交为 `dc92b6d2f361064d3e9e53ce5de92f611db77220`，需取得上游完整仓库和递归子模块，再把本项目 `src/moonlight-qt/app/` 覆盖到其 `app/`，把 `src/mslink/` 放到其 `mslink/`。本机构建对应 Qt 6.9.3 msvc2022_64、MSVC 14.44，先准备上游 Windows 依赖和静态子库，再用 qmake/nmake 构建 app。完整源码依赖以该上游提交及其子模块为准，不要仅编译覆盖层。

控制台可以单独构建：在 VS x64 开发环境中，Qt qmake 指向 `src/host-console/host-console.pro` 后运行 nmake。中文路径下 RC 资源编码需使用 UTF-8 code page，或使用 ASCII 构建目录。`gui-action.ps1` 放在被控端安装根目录的 `_internal/`。发布时同时部署 Qt 与匹配的 MSVC 运行库。

## 已验证及边界

已完成两个程序的编译、真实窗口检查、两份 Inno 安装包编译；隔离测试验证了设置保存、无关字段保留、缺少第二份配置时不部分修改第一份配置。检查了实际打包输入清单，排除配置、凭据、日志、转储；网络示例不指向私人服务。

尚未完成干净虚拟机的完整安装/卸载、Win10 崩溃回归、UAC 服务启停与长时间跨网游戏验收。没有为测试停止本机正在使用的 Sunshine/mslink。界面更新不能证明鼠标断触或底层传输问题已经修好。

控制台当前读取的是本机 IPv4 TCP 监听信息，端口可能由其他进程占用；它不验证实际服务身份、UDP、FRP、公网、配对状态或正在使用的会话。日志脱敏覆盖凭据关键词和 IPv4，导出分享前仍需人工检查域名、IPv6 和设备信息。

## 下一轮验收

1. 在干净 Win10 / Win11 各安装一次：普通用户启动、测试连接、重复启动、关闭到托盘、卸载，核对加载的 VC143 运行库版本。
2. 在专用测试主机验证 UAC 允许/取消、启动/停止/重启、保存失败、配置备份与进程归属；不要在承载当前远程会话的主机上做中断测试。
3. 局域网与真实跨网分别运行桌面和游戏，记录画面、声音、输入及传输模式；覆盖焦点丢失、菜单开关、相对/绝对鼠标模式、断线重连。
4. 后续控制台应加入带身份验证的本地状态 API，以实际进程、会话、输入与媒体计数替代端口观察；完成干净环境安装验收后再考虑转正式版。


## 第二轮：现代 IT 工作台与真实遥测

两端新增工作空间侧栏、实时指标和 `Powered by jianhx2026` 署名。主控端采用深色蓝灰配色，被控端采用深色导航与浅色数据卡片。

被控端从同目录 `mslink-status.json` 读取实际进程的遥测，验证进程路径、schema 和 5 秒新鲜度。展示已认证隧道客户端、设备名、时长、传输模式、隧道 RTT、发送速率及 60 点趋势。新版主控端每秒回传真实解码统计：渲染帧率、媒体码率（编译启用时）、网络丢帧、解码/渲染/排队耗时及主机处理时间。无采样显示“—”；停止串流超过 5 秒视为过期。媒体网络丢帧不等同于 IP 丢包，隧道 RTT 不等同于端到端鼠标响应时间。旧版客户端没有媒体回传，需两端一并升级。

遥测通过认证后的现有 TCP 隧道承载，单条上限 8 KB，不新增公网管理端口。隧道 CLI 在线程外每秒原子写本地 JSON，历史 JSONL 文件最多约 1 MB，轮转保留一份。文件可能包含设备名，应当脱敏后分享。当前隧道设计仍只支持单个认证客户端，不能把多个已配对设备当作多个在线会话。

本轮修复了下行以毫秒时间充当 UDP 包序号、认证前更新防重放状态、UDP 恢复误用循环计数和流回切后仍从 TCP 响应的问题。改为独立递增序号、认证后的 64 包滑动窗口、真实认证 ACK 三次恢复，并在 UDP 流恢复时切回对应返回路径。这些修复不构成对现有自定义认证/密钥传输的全面安全验收。

已通过原有 TCP/UDP 回显、并发 TCP、100 个 UDP 突发包、乱序/重复/过旧/序号回绕，以及独立双进程的设备名、RTT、JSON 与新鲜度检查。媒体指标已接入真实 FFmpeg 窗口统计，但尚未完成新版本跨机游戏和卡顿回归。

安装包内置微软签名有效的 VC++ x64 Redistributable 14.51.36247.0。安装前检查两个注册表视图中的 x64 runtime，缺失或低于 14.44.35112 时先运行 `/install /quiet /norestart`，失败阻止安装，3010/1641 标记需要重启。仍随程序保留匹配的 app-local CRT。此路径已经编译检查，未在本机卸载运行库来模拟干净 Win10。
