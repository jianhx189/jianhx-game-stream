MiniStream 2.1.3

隧道队列与帧上限、非阻塞握手、主控端 DPAPI 凭据与被控端口令 stdin 传递。

这次改了什么

  • 每连接发送队列 4 MiB 硬上限，整帧先预留再入队；空间不足整帧拒绝，入队/发送失败向上返回，不再静默丢数据。
  • TCP 单帧 64 KiB 上限，帧读取缓冲区有界，读到 8 字节帧头即拒绝超长帧。
  • 被控端握手非阻塞：最多 8 个 pending、单个 5 秒超时；新会话认证后关闭其余 pending，仍只保留一个已认证客户端。
  • seq == highest 的副本现在计为重复，冗余副本与真实丢包分开统计。
  • 新增队列/帧白盒测试与握手集成测试，CTest 共四项，本机 4/4 通过；--password-stdin 启动脚本实测通过。
  • 主控端隧道与 Sunshine 口令改用当前 Windows 用户 DPAPI（dpapi:v1:），旧明文 ini 用 QSaveFile 原子迁移。
  • 被控端 mslink 新增 --password-stdin，安装脚本经标准输入传口令；日志不再记录隧道/Sunshine 口令；ini、安装信息与安装日志 ACL 收紧到 SYSTEM / Administrators / 安装用户。
  • 新安装口令要求 12–64 字符，升级保留的旧口令可用但建议更换。

安全边界

DPAPI 只保护同一 Windows 用户可解的本地文件：程序内存中口令仍是明文，网络传输也没有因此加密。自定义隧道认证与 TCP 明文会话密钥没有变化，不是端到端加密 VPN。回退到 2.1.2 及更早版本、或更换 Windows 用户后需要重新填写口令；此前通过聊天、工单、截图或旧安装信息分享过隧道/Sunshine 口令的，请立即轮换。

升级与校验

结束当前串流，在已有安装目录覆盖升级并保留个人配置，两端建议使用相同版本。主控端旧式配置会在首次载入时迁移为 DPAPI 密文；回退旧版需重填口令。只打开新面板不会升级旧后台。

用 PowerShell 的 Get-FileHash 文件名 -Algorithm SHA256 与同版 SHA256SUMS.txt 对照。Release 同时提供构建清单和源码；哈希在安装包编译完成后生成，不能沿用上一版。

验证范围

本轮已完成：本机回环 CTest 4/4（UDP 回包源地址、队列/帧边界、握手集成、隧道自检）与 --password-stdin 启动实测。两端最终构建与两份安装包编译以发布清单生成时的记录为准，本页不预先宣称已通过。干净 Win10/Win11 安装、所有 GPU/驱动组合、高码率弱网与长时间跨网串流尚未验收；2.1.2 的真实转发 UDP 修复结论沿用，新的真实链路媒体串流仍需单独验收。
